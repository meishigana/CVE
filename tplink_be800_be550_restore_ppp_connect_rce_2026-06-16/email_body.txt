Suggested title:
TP-Link Archer BE800 and BE550 unsafe authenticated configuration restore to PPP connect root command execution

Summary:
The affected firmware GPL source contains LuCI configuration restore handlers that stream an authenticated administrator-uploaded backup archive directly into:

tar -xzC/ >/dev/null 2>&1

Because extraction is rooted at "/" and no archive member whitelist is applied, a crafted backup archive can contain a normal relative member such as "etc/config/network". This writes "/etc/config/network" on the device.

The strongest current command execution chain is through PPP configuration. A restored network config can define a proto "ppp" interface with attacker-controlled option "connect". TP-Link's PPP netifd helper passes that value to root "/usr/sbin/pppd" as:

connect
<attacker command>

The TP-Link local pppd source treats "connect" as a shell command string and executes it through "/bin/sh -c" on the tty-channel PPP path. The command can be triggered when the restored interface is brought up through LuCI apply, network restart, /sbin/ifup, or reboot.

This issue requires authenticated administrator access to the router management interface. It is not currently claimed as unauthenticated RCE.

Verified code path:
Authenticated LuCI restore upload
-> tar -xzC/ with extraction root "/"
-> restored /etc/config/network
-> netifd PPP helper reads option connect
-> /usr/sbin/pppd receives connect "<attacker command>"
-> pppd tty-channel path executes the connect command through /bin/sh -c

Proof of concept:
A benign local verifier for the primary PPP chain is included in the evidence repository:

verify_tplink_be_restore_ppp_connect_rce_chain_2026_06_16.sh

The verifier creates a backup archive containing:

etc/config/network

with this benign PPP marker configuration:

config interface 'pocppp'
        option proto 'ppp'
        option device '/dev/null'
        option username 'poc'
        option password 'poc'
        option connect 'id > /tmp/tplink_be_ppp_connect_poc'

The verifier confirms that the crafted archive layout matches the vulnerable restore semantics and that the "connect" value reaches the root pppd argv stream on both BE800 and BE550 GPL PPP scripts.

Supporting impact:
The same unsafe restore primitive can also write "/etc/rc.local". OpenWrt executes "/etc/rc.local" through "/etc/init.d/done" after reboot. This is supporting impact only; the primary CVE chain is the restored PPP "connect" option reaching root pppd.

I did not find a public record explicitly covering Archer BE800 v1 firmware 1.4.1 Build 20260401 or Archer BE550 v2 / BE9300 v2 firmware 1.3.1 Build 20260403 with the restore-to-PPP connect chain or the broader restore-to-rootfs write primitive.

No existing CVE was found that covers this exact combination:
TP-Link Archer BE800 v1 1.4.1 Build 20260401 / Archer BE550 v2 or BE9300 v2 1.3.1 Build 20260403 + unsafe configuration restore extraction under "/" + restored /etc/config/network + PPP connect command execution through pppd.

Duplicate or merge risk remains because the root cause is similar to broader unsafe restore/import vulnerability families.

CVSS rationale:
This score is conservative. It assumes the attacker needs valid administrator credentials and access to the management interface from the local/adjacent network. If the management interface is reachable from a broader network, or if the CNA treats web-admin-to-device-root as a stronger privilege boundary, the score may be adjusted.

Suggested remediation:
- Do not extract uploaded backup archives directly under "/".
- Extract to a temporary directory and validate the complete archive manifest first.
- Use a strict backup-file whitelist.
- Reject absolute paths, ".." path components, symlinks, hardlinks, device nodes, startup-controlled paths, and service execution hooks.
- Do not preserve attacker-controlled ownership, mode, or special-file metadata.
