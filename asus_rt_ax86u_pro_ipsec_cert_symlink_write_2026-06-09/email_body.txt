ASUS RT-AX86U Pro firmware 3.0.0.6.102_37436 upload_server_ipsec_cert.cgi authenticated IPsec certificate archive symlink traversal arbitrary file write

Summary:
The ASUS RT-AX86U Pro firmware 3.0.0.6.102_37436 web management interface appears to contain an authenticated arbitrary file write primitive in the IPsec server certificate upload handler. The endpoint upload_server_ipsec_cert.cgi accepts a certificate archive and reaches libwebapi.so!upload_server_ipsec_cert_cgi. That function extracts /tmp/server_ipsec_file/server_ipsec.tgz into /tmp/server_ipsec_file with a tar command constructed as "tar -xzf %s -C %s".

The command arguments are fixed paths, so this is not shell metacharacter command injection. The issue is unsafe archive extraction. The handler does not prevent archive-contained symbolic links. A crafted tar archive can first create a symlink inside the extraction directory and then write a following archive member through that symlink outside the intended directory.

Verified code path:
upload_server_ipsec_cert.cgi -> httpd upload handler/post handler -> libwebapi.so!upload_server_ipsec_cert_cgi -> snprintf("tar -xzf %s -C %s") -> system()

Root cause:
The IPsec certificate upload handler extracts attacker-supplied archive content with tar without rejecting symlinks or validating the resolved path of each archive entry. When tar processes an archive member such as "linkout -> /tmp" followed by "linkout/asus_http_upload_symlink_write", the second member is written through the symlink to /tmp/asus_http_upload_symlink_write, outside /tmp/server_ipsec_file.

Example laboratory payload archive entries:
linkout -> /tmp
linkout/asus_http_upload_symlink_write

Observed write target in the lab reproduction:
/tmp/asus_http_upload_symlink_write

Observed marker content:
HTTP_SYMLINK_WRITE

Impact:
An authenticated administrator can upload a crafted IPsec certificate archive that writes attacker-controlled content outside the intended temporary extraction directory. This may allow tampering with runtime files, service disruption, or follow-on exploitation if sensitive writable targets are reachable on a physical device. The current evidence proves an authenticated arbitrary file write primitive. It does not yet prove stable remote code execution.

Suggested CVSS v3.1:

CVSS rationale:
This score is intentionally conservative. The vulnerable endpoint is a network-reachable web management endpoint, but the current evidence treats administrative authentication as required. The primitive affects integrity because attacker-controlled content can be written outside the intended extraction directory in a privileged firmware runtime context. Confidentiality impact has not been demonstrated. Availability impact is rated Low because malicious overwrite targets may disrupt services. Suggested remediation:
- Do not extract untrusted certificate archives with raw tar -xzf.
- Reject archive entries that are symbolic links or hard links.
- Reject absolute paths, parent-directory path components, and entries whose resolved path escapes the intended extraction directory.
- Use a private temporary extraction directory and validate every archive entry before writing it.
- Prefer structured archive extraction APIs with explicit link/path controls.
- Run upload handling code with least privilege where possible.
- Add regression tests for archive-contained symlinks, hard links, absolute paths, and parent-directory paths.
